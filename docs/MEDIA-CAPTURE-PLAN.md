# Real media capture plan

Status: **OPEN — maintainer must supply or approve real screenshots and a demonstration video.** Artwork is illustrative and must not be presented as launcher evidence.

Use disposable profiles, test instances, a test account if permitted, neutral window chrome, and a clean desktop. Hide account names, tokens, local private paths, server addresses, notifications, bookmarks, and unrelated windows.

## Screenshots

1. **Multi-instance installation:** open one mod's selector with at least three clean test instances showing selected, not selected, unavailable, and (if safe) installed/uninstall states. Include the visible text key.
2. **Uninterrupted browsing:** keep a substantial Content Hub description visible while a completed-install notification/status is also visible; capture enough context to show the page did not navigate to Library.
3. **Preferred Mods:** show the reusable list, enabled/disabled entries, Apply to Instances, compatibility results, and Skip/Install choices.
4. **New instance creation:** show the optional Preferred Mods control or resulting explicitly enabled workflow. Capture both label and explanation.
5. **Privacy:** capture only privacy behavior actually visible in the build. If no truthful UI exists, use a terminal verification result labelled as technical evidence, not a fabricated settings screen.

Capture PNG at native resolution, crop only private/irrelevant chrome, keep text legible, and save approved files under `media/screenshots/` with a short provenance note.

## Demonstration storyboard (about 2–3 minutes)

1. On an isolated untouched launcher, start a mod install while reading another description and show the navigation interruption.
2. On the workflow build, repeat and show the install completing while Content Hub stays in place.
3. Select one mod for several compatible instances and explain all text/icon states without relying on colour.
4. Add two or three test mods to Preferred Mods, disable one, review compatibility, skip one, and apply the remainder.
5. Create a test instance with automatic application explicitly enabled; show compatible installs and the report for skipped unsupported entries.
6. Explain that the privacy patch narrows inspected launcher routes but is not a firewall or anonymity tool; point to the threat-model document.

Keep the untouched and patched clips clearly labelled. Avoid edits that imply a result not captured in real time. Save the approved video link/provenance under `media/README.md`; do not commit large video files without a deliberate hosting decision.
